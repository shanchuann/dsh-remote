# 项目列表完整性修复

旧手机列表读取前 100 条会话后停止，再根据这些会话反推项目。当前真实宿主有 236 条会话，前 100 条恰好只覆盖 7 个项目，因此较早项目被漏掉。仅修正项目成员关系不能保证项目清单完整。

## 实现

- 插件 0.1.10 的会话列表额外返回完整 `workspaces` 清单，包含空项目，顺序与桌面注册表一致，不受会话分页限制。
- 手机 0.1.12 / versionCode 12 同时读取完整项目清单和全部会话分页，按真实 Workspace ID 放入项目；空项目也可展开并在其真实 ID 下新建对话。
- 注册表及项目成员关系按每次请求快照读取一次，避免为每条会话重复读取实体 getter。
- 未分组对话另列，子智能体仍只在所属对话的子智能体面板中查看；缺少清单字段的旧插件保留兼容行为。断开连接或切换至旧宿主后清除上次清单。

## 验证

- App 130 项测试、插件 96 项测试通过，失败、取消、跳过均为 0；App 类型检查、Expo lint、Android 导出通过。
- 回归覆盖：17 个项目仅 7 个包含主对话、空项目、只有子智能体的项目、前 100 条全为子智能体而主对话在后续页、项目重命名/移除、空清单与旧插件、断开后清空。
- 已通过官方 CLI 将实际桌面插件从 0.1.9 升级至 0.1.10。更新前确认没有会话运行，正常退出并重开桌面宿主，恢复原有会话页面。
- 实际 HTTP 接口经手机同一 `readSessionCatalog` 和 `groupSessionProjects` 代码核对：3 页分别为 100、100、36 条，每页均返回全部 17 个注册项目，ID 与顺序逐项匹配桌面注册表。主对话 74 条，另外 162 条子智能体不进入项目对话列表。此前迁入 dsh-remote 的三条会话仍属于目标 Workspace。
- 当前原始数据另外有 6 条未分组主会话，因此显示 17 个注册项目和一个“未分组”分组，共 18 个卡片。这 6 条包括空白及已归档历史会话；本轮没有迁移、删除或恢复它们，也没有用固定数量隐藏数据。
- 核验用本地配对设备已撤销，没有发送模型消息。临时数据及日志位于 `D:/Code/dsh-remote.testhome/project-catalog`。
