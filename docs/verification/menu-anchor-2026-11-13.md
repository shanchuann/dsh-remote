# 添加图片入口跟随输入框

## 问题

在对话输入框弹出键盘时点「+」，弹出的「添加图片」浮层停在屏幕中部，和输入框之间隔着任务面板；键盘收起后浮层仍留在原处（见 `screenshots/menu-anchor-before.png`）。另外，浮层以「+」按钮为锚点，输入框带图片附件时会压住附件行。

## 根因

- 菜单在独立的窗口/Modal 中展开（`app/src/components/overlay.tsx`）。Android 上这个新窗口取得焦点后会收起输入法，而菜单位置是在打开前用 `measureInWindow` 量好的：量到的是键盘弹起时的输入框位置，键盘一收，输入框落回底部，浮层就被留在原处。
- 菜单只按触发按钮测量，没有覆盖「整个输入框」的概念，带附件时输入框变高（附件行在上方），浮层仍贴着「+」按钮上沿，因此压住附件。

## 改动

- `app/src/components/menu/menu.tsx`
  - 打开前若键盘可见，先 `Keyboard.dismiss()`，轮询测量触发视图直到位置稳定（最多 800ms）再展开，避免在滑动过程中定位。
  - 展开后 700ms 内继续跟随触发视图，并在 `keyboardDidShow/keyboardDidHide` 时重新测量，键盘此时仍在变化也能贴合。
  - 新增 `anchorRef`：面板按指定视图（整块输入框）而不是触发按钮定位。
  - 关闭时用代次计数取消等待中的打开，避免「关闭后又被迟到的打开顶回来」。
- `app/src/components/prompt-input/prompt-input.tsx`
  - 给输入框外壳加 ref，并作为 `anchorRef` 传给「+」菜单，浮层按整个输入框（含附件行）定位。

## 验证

Android 36 模拟器（1080×2400，density 420，`emulator-5554`），隔离 fixture 宿主（`10.0.2.2:18896`，1 个项目 1 条会话，无真实模型请求），安装本工作区构建的 release APK：

| 场景 | 结果 | 证据 |
|---|---|---|
| 键盘弹出时点「+」（修复前） | 浮层在屏幕中部，键盘收起后悬空 | `menu-anchor-before.png` |
| 键盘弹出时点「+」 | 键盘先收起，浮层出现在输入框正上方：菜单项 y 2039–2140，输入框顶 2187 | `menu-anchor-keyboard.png` |
| 键盘关闭时点「+」 | 直接贴输入框上方打开，无等待感 | `menu-anchor-after.png` |
| 输入框带 1 张图片附件时点「+」 | 浮层在附件行（y 2104–2167）上方：菜单项 y 1929–2030，附件完整可见 | `menu-anchor-attachment.png` |
| 点「添加图片」 | 正常打开系统照片选择器，可选中并回到输入框生成附件 chip | 模拟器实测 |
| 快速关闭再打开、点头部「更多选项」菜单 | 正常；头部菜单仍贴在三点按钮下方 | 模拟器实测 |

静态与自动回归：`npx tsc --noEmit`、`npx expo lint` 通过；App 单测 144 项通过（含工作区并行任务的用例）。

## 边界

- 未在用户的小米实体机上安装验证；模拟器为 x86_64 release 构建。
- 本次验证时工作区还有其它并行任务的未提交改动，构建产物同时包含那些改动；此修复本身只涉及上面两个文件。
- iOS 侧走 `FullWindowOverlay`，本次未在 iOS 设备上复验键盘行为，但跟随/重测量逻辑与平台无关。
